# NixSoma Capability Map

Updated: 2026-08-02

This is the canonical progress view. Historical phase numbers and test counts
do not determine completion. A capability advances only when its operator
workflow, owner, durable state, recovery boundary, Observer readback, and
representative evidence agree.

## Newly Deployed Workflow

```text
operator arms finite mission authority
-> supervisor checkpoints one epoch before execution
-> existing bounded window owner consumes at most one 1-20 step session
-> Observer shows progress, checkpoint, deadline, circuit, and stop reason
-> mission pauses/cancels at an epoch boundary
-> Core restart requires exact explicit re-arm
-> operator may renew only another finite epoch/deadline grant
```

The mission accepts 1-32 epochs initially, at most 32 more per renewal, and at
most 256 during one mission lifetime. Each authority grant is at most seven
days and cannot extend the live horizon beyond 30 days. It is renewable, not
uninterruptible or unbounded.

## Next Vertical Route

The next missing autonomy behavior is a reviewed finite mission worklist. It should let
the operator bind a bounded set of task blueprints to one mission and let the
mission issue only the next reviewed item at an epoch boundary. This closes the
task-supply gap without giving a provider open-ended task creation or policy
authority. Adaptive ranking, physical Phase D, and wider body actions remain
separate subsequent routes.
